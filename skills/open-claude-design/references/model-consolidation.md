# Finish in the canonical model

Use this when refining an existing product whose Claude Design project has a unified model. A user-requested standalone exploration can remain separate.

1. Identify the canonical root page and its supporting files before creating a focused preview. Record which draft files this task creates. Preserve the App and Website as separate canonical models when they describe different products.
2. A focused preview may help the user review a change quickly. Once its direction is accepted, integrate the actual components, states, copy and interactions into the canonical model. Do not replace a complete model with the smaller preview or leave two conflicting versions as equal authorities.
3. Re-read the affected remote files and etags before merging. Preserve unrelated routes, onboarding, settings, other people's edits and comments. Merge content conflicts rather than overwriting them. Use the existing guarded push/synchronization workflow.
4. Check the change in the model's real surrounding flow: navigation into and out of the screen, the primary action, relevant empty/waiting/error states, and representative narrow/wide and theme variants. A good isolated card is not proof that the complete page works.
5. Read back the merged files and confirm that the canonical page remains listed and renders. Verify code against this integrated revision when implementation is part of the task. Keep the canonical page's durable URL as the deliverable.
6. Retire temporary duplicates only after the merge is verified. Check references, preserve a local recovery copy, and retain any user comments. Remove local scratch files only when they were created for this task and have no remaining purpose. Use the specialized exact-path deletion helper for remote retirement, within the user's existing authorization; do not delete unrelated or user-maintained pages. An explicit merge-and-cleanup instruction for named drafts already authorizes their scoped retirement and does not need a routine second confirmation. If remote retirement is not authorized, keep it clearly identified as a superseded draft and report that narrow remainder without blocking independent work.

When a user has requested automatic merge-back and cleanup as their ongoing design workflow, apply that preference on subsequent refinements. Do not wait for another reminder at the end. It does not authorize deleting existing pages outside the task or changing sharing and access.

The completion record names the canonical page, the integrated revision, the interactions checked, and any retained draft with its reason. Do not call the project synchronized while the accepted change exists only in a separate preview.
